SARKARIJOBALERT — OFFICIAL GOVERNMENT JOB SCANNER

WHAT IT DOES
- UPSSSC, UPPSC, UP Police and UP NHM are checked first for vacancies, Admit Cards and Results.
- Admit Card and Result scanning is UP-only; verified updates from official UP portals are collected as Drafts for admin review.
- Duplicate Admit Card/Result notices are not inserted again; unofficial sources or updates whose official UP origin cannot be verified are not published.
- Central/national recruitment portals are checked after UP sources.
- GitHub Actions runs the scanner every 6 hours; manual scanner run is also available.
- Uses retry/backoff for temporary network errors and keeps TLS certificate verification enabled.
- Reads official HTML recruitment pages and linked official notification PDFs.
- Extracts vacancy count, qualification, dates, fees, age limit and selection process when readable.
- Requires a clear official recruitment notice and at least two independently confirmed core facts: future last date, vacancy count and qualification.
- Missing fields stay blank for admin review; expired deadlines, weak evidence and unclear titles are skipped.
- Automatically collected vacancy, Admit Card and Result entries are saved as Drafts first. An admin must review the official source and publish manually.
- Vacancy Drafts require a clear title and at least two of these verified facts: future last date, vacancy count, qualification. A missing third fact is left blank for the admin to verify.
- Scanner-created entries remain Draft until a human admin reviews and publishes them. This editorial review is important for accuracy and AdSense content quality.
- UP Admit Card/Result collection follows separate official-UP-source verification and does not require a PDF or vacancy fields; entries still remain Draft until admin approval.
- Existing jobs are checked by URL and normalized title/department before insertion.
- Published job sitemap is generated from the existing Supabase jobs table after each scanner/cleanup workflow run. It includes public ?job=ID deep links, excludes Drafts and expired Vacancy posts, and adds lastmod where available.
- The workflow commits sitemap-jobs.xml only when its content changes; GitHub Actions needs contents: write for this step.
- Inserts new rows only; it does not update existing records.
- Uses the existing public.jobs columns. No schema change is required.
- Vacancy category uses the existing database value: Latest Jobs.

SCHEDULE
- Scanner: every 6 hours (UTC cron 17 */6 * * *; India time 05:47, 11:47, 17:47 and 23:47).
- Cleanup: daily at 01:05 India time (UTC cron 35 19 * * *).
- Clicking Run workflow manually runs the scanner only. It does not trigger deletion cleanup.

SAFETY
- TLS verification remains enabled. Certificate errors are logged and skipped, never bypassed.
- Only official government domains/approved official portals are accepted, including after redirects.
- Expired or unverified deadlines are skipped.
- For the vacancy scanner, results, admit cards, interview notices, corrigenda, tenders and similar non-vacancy notices are filtered out. UP Admit Cards and Results are handled by a separate UP-only scanner.
- An official PDF is preferred for vacancy verification, but all scanner-created entries remain Draft pending human review.
- For vacancy Drafts, at least two core facts (future last date, vacancy count, qualification) must be confirmed. Missing facts are left blank for human review.
- A PDF is preferred and linked when available, but a PDF is not required to save a Draft if the official HTML notice provides enough evidence. Every scanner-created entry remains Draft.
- A future last date must be confirmed from the official source before an admin publishes a vacancy.
- Missing optional details are left blank; the scanner does not guess them.
- The scanner does not update or delete existing jobs.
- Cleanup runs only on its daily schedule and affects every Latest Jobs vacancy (manual or scanner-created, Draft or Published) once the 30-day grace period has passed.
- Manual workflow runs do not run cleanup.
- Website UI, admin logic, schema, Cloudflare Worker, ticker and push notifications are not changed.

AUTOMATIC EXPIRY + DELETION (ALL VACANCIES)
- Every Vacancy, whether manually created or scanner-created, remains eligible for deletion 30 full calendar days after its last_date.
- The daily cleanup can permanently delete the expired vacancy regardless of Draft/Published status.
- Cleanup is restricted to vacancy categories Latest Jobs, Vacancy and Jobs, with last_date at least 30 days past. It applies to manual and scanner-created vacancies, regardless of Draft/Published status. The delete request is scoped to the exact eligible row IDs returned by the category/date filter.
- It does not delete Admit Cards, Results, Education Guides, or rows without last_date.
- This is permanent deletion, not archive. Keep regular Supabase backups if recovery is required.

POST DESCRIPTION REQUIREMENT (MANUAL + AUTOMATIC)
- Every Vacancy, Admit Card and Result post must have a meaningful, post-specific description in the Complete Details section.
- The description must be based on that post's title and verified official information; do not use generic filler text such as "Verified update detected...".
- Vacancy descriptions should explain the post/recruitment, eligibility, selection process and application steps when those details are officially available.
- Admit Card descriptions should explain the exam/admit-card update, exam date or release details when verified, and download instructions.
- Result descriptions should explain which result was declared, result-checking steps, and merit-list/cut-off information only when officially available.
- Apply this requirement to both manually entered and scanner-created posts.
- Never invent missing dates, fees, eligibility, vacancy counts, cut-offs or links. Leave unavailable details blank or clearly state that the official notice should be checked.
- Preserve the existing website design and admin/database structure unless a separate approved change is requested.

ARTICLE LANGUAGE & CLEAN TEXT
- Scanner detects Hindi/Devanagari from the complete official notice text, not only the job title. Hindi notices get a Hindi article; English notices get an English article.
- Official facts are retained in their source wording; the scanner does not invent or silently translate qualification, fee, age, selection or dates.
- Extracted PDF text whitespace is normalized. Common mojibake/replacement-character corruption is rejected from structured fields rather than shown as factual details.
- Vacancy article descriptions are written as short, separated paragraphs. The job detail page uses the article language for field labels and separates paragraphs for mobile readability.
- If extraction is unclear, the field is left blank or marked for official-notification verification. All scanner entries remain Draft until an admin checks the original source.
