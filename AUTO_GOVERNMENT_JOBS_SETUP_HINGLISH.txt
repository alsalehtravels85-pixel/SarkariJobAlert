SARKARIJOBALERT — OFFICIAL GOVERNMENT JOB SCANNER

WHAT IT DOES
- UPSSSC, UPPSC, UP Police and UP NHM are checked first.
- Central/national recruitment portals are checked after UP sources.
- GitHub Actions runs the scanner every 6 hours; manual scanner run is also available.
- Uses retry/backoff for temporary network errors and keeps TLS certificate verification enabled.
- Reads official HTML recruitment pages and linked official notification PDFs.
- Extracts vacancy count, qualification, dates, fees, age limit and selection process when readable.
- Requires a clear recruitment notice and an explicitly labelled future last date.
- If essential information is missing, the candidate is skipped rather than cluttering Admin Drafts.
- Automatically publishes only when an official PDF is readable, contains clear recruitment details and has its own explicit future last date.
- If the PDF is missing, unreadable, incomplete or does not independently verify the deadline, the vacancy is saved as DRAFT.
- HTML-only notices can create Draft entries but are never auto-published.
- Existing jobs are checked by URL and normalized title/department before insertion.
- Inserts new rows only; it does not update existing records.
- Uses the existing public.jobs columns. No schema change is required.
- Vacancy category uses the existing database value: Latest Jobs.

STARTER SOURCES
UPSSSC, UPPSC, UP Police, UP NHM, NCS Government Jobs, UPSC, SSC, IBPS, India Post, RBI, SBI Careers, DRDO, ISRO, Indian Railways, NABARD, SEBI, TNPSC, Kerala PSC, RPSC, BPSC, MPPSC and Employment News.

GITHUB ACTIONS SECRETS
The workflow uses the existing repository secrets:
- SUPABASE_URL
- SUPABASE_SERVICE_ROLE_KEY
If already configured, do not change them. Never place the service-role key in website files or commit it to Git.

SCHEDULE
- Scanner: every 6 hours (UTC cron 17 */6 * * *; India time 05:47, 11:47, 17:47 and 23:47).
- Cleanup: daily at 01:05 India time (UTC cron 35 19 * * *).
- Clicking Run workflow manually runs the scanner only. It does not trigger deletion cleanup.

4. Supabase > Table Editor > jobs: check newly created Published and Draft rows.
5. Review auto-published PDF-backed vacancies too; scanner checks reduce risk but do not replace human review.

SAFETY
- TLS verification remains enabled. Certificate errors are logged and skipped, never bypassed.
- Only official government domains/approved official portals are accepted, including after redirects.
- Expired or unverified deadlines are skipped.
- Results, admit cards, interview notices, corrigenda, tenders and similar non-vacancy notices are filtered out.
- An official PDF is mandatory for automatic publishing.
- PDF-less notices are Draft only. A PDF that is unreadable or lacks its own clear recruitment details and future last date is also Draft.
- A future last date must be present in the PDF itself for automatic publishing.
- Missing optional details are left blank; the scanner does not guess them.
- The scanner does not update or delete existing jobs.
- Cleanup runs only on its daily schedule and only affects scanner-managed Published Latest Jobs after the 30-day grace period.
- Manual workflow runs do not run cleanup.
- Website UI, admin logic, schema, Cloudflare Worker, ticker and push notifications are not changed.

AUTOMATIC EXPIRY + DELETION (SCANNER-MANAGED LATEST JOBS ONLY)
- A vacancy with a verified official PDF may be auto-published by the scanner; PDF-less or uncertain notices remain Draft.
- Once Published, it remains visible for at least 30 full calendar days after its last_date.
- After the full 30-day grace period, the daily cleanup can permanently delete that scanner-managed row.
- Cleanup is restricted to category=Latest Jobs, status=published, source_url containing #sja-auto-scanner-managed, and last_date older than the 30-day cutoff.
- It does not delete manually created jobs, Admit Cards, Results, Education Guides, Drafts, or rows without last_date.
- This is permanent deletion, not archive. Keep regular Supabase backups if recovery is required.
